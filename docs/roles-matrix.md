## Обозначения
- ✅ — полный доступ (чтение + изменение)
- 👁 — только чтение / частичный доступ
- ❌ — доступ запрещён

## Реализация в Django

Роли — это `auth.Group`, права — `auth.Permission` из моделей:

| Роль (Group) | Ключевые permissions |
|---|---|
| `registrar` | `patients.*`, `appointments.*`, `queue.*` (add/change/view/delete queueticket) |
| `administrator` | все права выше + `schedule.*` (справочники) |
| `doctor` | `appointments.change`, `queue.view/change_queueticket` (+ object-level: только своя очередь) |
| `management` | только `*.view`, включая `schedule.view_department` и `queue.view_queueticket` (без действий) |

**Object-level access** (врач видит только своё) реализуется:
- фильтром `doctor=request.user.doctor_profile` в `apps/queue/views.py` (`cabinet`, `cabinet_action`);
- фильтром `doctor = свой профиль` в `apps/reports/views.py` (`_doctor_scope`) — врач не может
  запросить чужие цифры даже вручную через `?doctor=<id>`;
- фильтром `?department=` в отчётах (`_department`) — он применяется только при `can_pick`,
  то есть для врача игнорируется: жёстко свой профиль, а не «свой отдел»;
- чужой кабинет по `?doctor=<id>` открывает только администратор/суперпользователь;
- проверкой `ticket.doctor == profile` в действии над талоном (см. `scripts/smoke.sh`, секции 11–14).
