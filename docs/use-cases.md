# Use Cases — «Регистратура»

Система автоматизации регистратуры медицинского учреждения.
Роли: **Регистратор**, **Администратор**, **Врач**, **Руководство**.

## Описание сценариев

### UC1. Авторизация
| | |
|---|---|
| **Актёры** | Все роли |
| **Предусловие** | Пользователь создан администратором, пароль задан |
| **Основной поток** | Ввод логина/пароля → проверка → вход → редирект на рабочий экран роли |
| **Альтернативные потоки** | Неверный логин/пароль → сообщение об ошибке, счётчик попыток |
| **Постусловие** | Создана сессия, записано событие аудита входа |

### UC2. Поиск пациента
| | |
|---|---|
| **Актёры** | Регистратор, Администратор |
| **Предусловие** | Пользователь авторизован |
| **Основной поток** | Ввод части ФИО / телефона / СНИЛС → список совпадений → выбор пациента |
| **Альтернативные потоки** | Совпадений нет → предложение зарегистрировать нового пациента (UC3) |
| **Постусловие** | Открыта карточка выбранного пациента (UC4) |

### UC3. Регистрация нового пациента
| | |
|---|---|
| **Актёры** | Регистратор |
| **Предусловие** | Поиск (UC2) не дал результатов |
| **Основной поток** | Заполнение ФИО, даты рождения, пола, телефона, адреса, СНИЛС → ввод полиса ОМС/ДМС → сохранение |
| **Валидация** | Обязательны ФИО и дата рождения; дубликаты по СНИЛС/телефону предупреждаются |
| **Постусловие** | Создана карточка, записано в аудит «создание пациента» |

### UC4. Просмотр карточки пациента
| | |
|---|---|
| **Актёры** | Регистратор, Администратор, Врач (только свои пациенты), Руководство (только чтение) |
| **Основной поток** | Открытие карточки → анкетные данные, полисы, история визитов и записей |
| **Постусловие** | — |

### UC5. Запись на приём
| | |
|---|---|
| **Актёры** | Регистратор |
| **Предусловие** | Выбран пациент (UC2/UC3) |
| **Основной поток** | Выбор специальности → выбор врача → отображение свободных слотов по расписанию → выбор слота и типа визита (первичный/повторный) → подтверждение → печать талона (UC7) |
| **Валидация** | Запрет записи в прошлое; слот не может быть занят дважды; проверка сроков действия полиса |
| **Постусловие** | Создана запись (статус «записан»), слот помечен занятым |

### UC6. Перенос / отмена записи
| | |
|---|---|
| **Актёры** | Регистратор, Администратор |
| **Основной поток** | Выбор записи → перенос на другой слот либо отмена с указанием причины |
| **Постусловие** | Старый слот освобождён, статус записи изменён, событие в аудите |

### UC7. Печать талона
| | |
|---|---|
| **Актёры** | Регистратор |
| **Основной поток** | От формы записи/очереди открывается страница печати (браузерный диалог печати) → на талоне: пациент, врач, кабинет, дата/время, номер очереди |

### UC8. Выдача талона очереди (без записи)
| | |
|---|---|
| **Актёры** | Регистратор |
| **Основной поток** | Выбор специальности → выдача номера → пациент ожидает вызова |
| **Постусловие** | Создан талон очереди (статус «ожидает») |
| **Реализация** | ⏳ вне MVP: талоны ведутся по записям (OneToOne), талон без записи не создаётся |

### UC9–UC11. Администрирование
| | |
|---|---|
| **UC9** | Управление справочниками: специальности, врачи (профиль, отдел, кабинет), кабинеты, **отделы** (`/schedule/departments/` — CRUD + M2M «специальности отдела», колонки «Специальности»/«Врачей»). **Валидация**: специальность врача обязана входить в выбранный отдел (`Doctor.clean()`), иначе ошибка формы. Список врачей фильтруется `?department=`+`?specialty=` (комбинируются; **каскад**: при выбранном отделе список специальностей ограничивается его M2M, несовместимая пара → 302 без `specialty`). Страница-структура `/schedule/structure/` — «отдел → специальность → врачи» + «врачи без отдела», открыта всем вошедшим. На странице специальностей — закреплённые врачи и отделы. Отдельно — «Кабинеты по этажам» (`/schedule/floors/`): группировка по корпусу/этажу с врачами и отделами, фильтры `?floor=`/`?department=`; в CRUD кабинетов — фильтр по этажу и колонка «Врачи» |
| **UC10** | Ведение недельных расписаний приёма: врач, день недели, интервал, длительность слота |
| **UC11** | Управление пользователями: создание, назначение роли (группы), блокировка |

### UC12–UC15. Кабинет врача
| | |
|---|---|
| **UC12** | «Моя очередь» (`/queue/cabinet/`): список на дату + карточки пациентов (полисы, прошлые визиты) |
| **UC13** | «Вызвать следующего» — на экране общей очереди (регистратор/администратор); врач принимает пациентов в кабинете |
| **UC14** | Проведение приёма: `start` → `complete` с заметкой врача (`Appointment.visit_note`) → запись «завершён» |
| **UC15** | Назначение повторного визита из приёма — одной кнопкой создаётся новая запись |

### UC16. Просмотр отчётов и статистики
| | |
|---|---|
| **Актёры** | Руководство (все отчёты), Администратор (все), Врач (только свои, object-level), Регистратор — ❌ |
| **Экраны** | `/reports/` — хаб с формой периода (по умолчанию 7 дней); `/reports/load/` — загрузка врачей; `/reports/no-shows/` — неявки; `/reports/flow/` — поток пациентов по дням |
| **Содержание** | Загрузка врачей: записи по статусам + % (активные+завершённые+неявки / все записи, без потенциала слотов); неявки: список + счётчик пациента; поток: таблица по дням + CSS-график |
| **Фильтры** | период `from/to` (auto-swap при `from > to`), врач, отдел и **специальность** (только для админа/руководства, комбинируются; для врача фильтры игнорируются — жёстко свой профиль). В «Загрузке врачей» — колонка «Отдел» |

### UC17. Экран вызова пациентов (табло)
| | |
|---|---|
| **Актёры** | Руководство (просмотр), система (обновление) |
| **Основной поток** | Отдельный полноэкранный режим ожидания: вызванный пациент, номер кабинета; авто-обновление (htmx polling) |

### UC18. Каталог врачей и карточка врача (без входа)
| | |
|---|---|
| **Актёры** | Пациент / посетитель (без учётной записи) |
| **Экраны** | `/doctors/` — каталог активных врачей; `/doctors/<pk>/` — карточка врача |
| **Основной поток** | Каталог открывается без аутентификации (ссылка есть на странице входа): карточки врачей с фото/инициалами, специальностью, отделом и кабинетом; фильтры `?department=` / `?specialty=` (каскад: специальности ограничены выбранным отделом) |
| **Содержание карточки** | ФИО, специальность и отдел (бейджи), кабинет с этажом/корпусом, стаж, био, недельное расписание приёма, кнопка **«Записаться на приём»** → `/appointments/booking/?doctor=<pk>` (предвыбор врача) |
| **Связи** | С врачами кликабельны с `/schedule/structure/`, `/schedule/floors/` и списка специальностей; CRUD `/schedule/doctors/` остаётся закрытым для анонимов (302) |

### UC19. Направление к подходящему свободному врачу
| | |
|---|---|
| **Актёры** | Врач (выписывает по своему приёму), Администратор (с карточки пациента), Регистратор (видит входящие, подбирает и записывает), Руководство (наблюдение) |
| **Экраны** | `/appointments/directions/` — входящие направления; `/appointments/directions/new/` — выписка; `/appointments/directions/<pk>/cancel/` — отмена |
| **Основной поток** | Врач из «Моего кабинета» (кнопка «Направить» на приёме) или администратор с карточки пациента выбирает специальность-цель и причину → направление (`Direction`, статус **new**) с номером `Н-NNNN` попадает регистратору |
| **Подбор** | `routing.find_candidates(specialty)`: только активные врачи нужной специальности, критерии по убыванию — **ближайший свободный слот** в горизонте 7 дней → **загрузка сегодня** → **этаж/кабинет** → ФИО; топ-5, без свободных слотов — исключается |
| **В списке** | Для каждого нового направления: карточки-кандидаты (ближайший слот, % загрузки) с кнопкой **«Записать»** → предзаполненная запись `?patient=&specialty=&doctor=&date=&direction=`; после выбора слота направление автоматически становится **booked** со ссылкой на запись; кнопка «Отменить» → **cancelled** |
| **Изоляция** | Врач видит только созданные им направления и выписывает их лишь по своим приёмам; регистратор/администратор — все; руководство — read-only (без кнопок); создание для регистратора запрещено (редирект на дашборд) |
